The ECHO platform has four parts:

a

ECHO Builder

A Docker image running Java 21, including the web-based front end. It is not part of the daily build and deployment.

b

Pipeline

The scripts needed to build the runtime flows are provided

c

Kubernetes Ingress

Configuration files

d

ECHO Runtime

Docker images running Java 21 that contain the flows. In bundle mode all flows go into one image; in per-flow mode each flow gets its own image.

Can be deployed on standalone servers, but ECHO includes features designed for Kubernetes

Can run side by side with legacy deployments, using Kubernetes Ingress routing

Can be deployed in bundle mode (all flows in one pod) or per-flow mode (each flow in its own pod)

Four parts. The Builder is where flows are designed and isn’t part of the daily build. The pipeline scripts, the Kubernetes Ingress files and the Runtime images are what go to production. Ingress routing means ECHO flows can sit alongside existing legacy services.
